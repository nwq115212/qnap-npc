# qnap-npc
威联通的npc安装包 使用yisier大佬的后继版本，使用的版本为v0.26.38：https://github.com/yisier/nps
## 适用范围

- Intel / AMD 的 x86-64 威联通 NAS；不支持 ARM 或 32 位 x86。
- 安装程序设置的最低版本为 QTS 4.5.4，Linux 内核需为 3.2 或更高。
- 使用 NAS 自带网页服务及管理员登录状态；无需 Docker、Python、Node.js 或额外管理端口。
- 保留用户提供的 NPC 可执行文件，不替换其版本或网络协议实现。其 Go 构建信息为 go1.24.9、linux/amd64、CGO_ENABLED=0。
- 当前未连接真实 NAS，尚未验证具体型号上的 QTS / QuTS hero 安装、网页认证和服务端连接；上述范围是构建目标，不是实机兼容性保证。

## 安装与使用

1. 以管理员身份登录威联通，在 App Center 选择“手动安装”。
2. 选择 `NPC_1.0.0_x86_64.qpkg` 并安装。
3. 此为个人制作的未签名应用。如果 App Center 因缺少数字签名拒绝安装，需在 App Center 设置中允许安装没有有效数字签名的应用，然后重试。不同系统版本的选项文字可能不同。
4. 在 App Center 打开 NPC。页面只有一个命令参数输入框和“保存并启动”按钮。
5. 输入实际参数，例如：

   ```text
   -server=你的服务器地址:8024 -vkey=你的密钥 -type=tcp
   ```

   也可粘贴：

   ```text
   ./npc -server=你的服务器地址:8024 -vkey=你的密钥 -type=tcp
   ```

6. 点击“保存并启动”。参数先保存成功，再停止旧进程并启动新进程。
7. 页面显示进程状态。是否成功连接、隧道是否可用，请在 NPS 服务端和实际访问端确认。

## 日常行为

- 第一次安装不填参数时，不启动 NPC 网络连接。
- App Center 中应用启用时，NAS 重启后恢复已保存参数。
- 停用应用会停止管理服务和 NPC；重新启用后读取已保存参数。
- 再次保存会重启 NPC。无效输入或写盘失败不会停止当前 NPC。
- NPC 自行退出后显示失败，不反复尝试错误参数；修改后重新保存，或在 App Center 重新启用。
- 同一包升级保留 `state/config.json`；卸载会删除配置，包括密钥。升级前可自行留存参数。
- 密钥输入默认隐藏，点击输入框时显示以便编辑，离开输入框后隐藏。配置和 NPC 工作目录仅系统管理员可读。
- 不把参数交给系统 shell，不支持 `install`、配置文件模式 `1`、重定向、管道或多个系统命令。
- 管理界面不提供原始 NPC 日志，避免日志中的密钥出现在网页或错误信息中；启动失败时显示简短说明。

## 常见情况

- **请先以管理员身份登录**：用 NAS 的同一个地址、同一浏览器重新登录管理员账号，再从 App Center 打开 NPC。普通用户无管理权限。若仍提示此信息，请反馈 NAS 型号和完整系统版本；不要提供密钥或登录 Cookie。
- **应用服务未运行**：在 App Center 停用后重新启用。仍失败时，请反馈型号、系统版本及安装或启动提示。
- **NPC 已退出**：检查服务端地址、端口、密钥、协议，以及参数是否被当前 NPC 版本支持。
- **进程运行中但不能访问**：该状态只表示 NPC 进程存在；继续检查 NPS 服务端在线情况和隧道配置。
